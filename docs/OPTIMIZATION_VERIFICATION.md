# DataAgent-Python 优化与验收记录

日期：2026-09-18。当前主项目为运行中的 DataAgent-Python，不再以 Java 项目为主。

## 1. 本轮完成的范围

- 网页和外部 MCP 共用查询、图表、分析及证据服务，避免两套结果逻辑。
- MCP 拆为 12 个工具；查询不强制画图，画图不强制写报告。完整请求仍可交给模型规划。
- 支持柱状、条形、折线、饼图、散点、热力图、堆叠柱状；模型选择图型和字段，数值只从保存的查询结果读取。
- 图表统计必须关联同源查询与图表。报告剔除模型自行生成的 ECharts 数据，附加经过校验的图表和 SQL 证据。
- 保存问题、业务依据、增强问题、真实 Schema、可行性、计划、原始/实际 SQL、结果、图表、统计与回答/报告，使用父引用及内容哈希。
- 已选表约束、只读 SQL 校验、结果上限、空值与截断提示、智能体归属和可选 API Key 校验。
- 中文流程名称、报告分组、同一轮内重复报告处理、默认展示 SQL 结果；节点的可重试错误不会直接中断整个前端流。
- 缺少归因字段不再阻止能够回答的比较；建议须说明依据及验证方式，不能伪称已证明因果。
- 用户原话不被改写结果替代；通用数值约束守卫拒绝丢失/改变显式年份和数量的改写，保留原话及被拒绝的提案。这不是针对“2015”的特例，也不是完整语义证明。
- 绘图不再被旧的 15 秒装饰性增强上限提前取消；默认遵循模型请求/重试预算，可显式另设阶段上限。绘图失败原因单独保存，整轮标为 partial。
- 需要澄清、等待审核、取消、失败与成功使用不同运行状态；MCP 完整请求读取同一持久化状态。
- 临时模型 HTTP 错误（408/429/500/502/503/504）与响应交付前的传输故障最多额外重试 2 次；上下文压缩使用独立预算。无效请求/认证错误不重试，流式响应交给消费者后不自动重放。
- 结构化输出区分 JSON 语法错误与 Schema 契约错误：类型/字段错误携带原始任务、Schema 与校验位置重新生成，不再用仅修语法的提示反复保留错误结构。
- 时间线网格项允许收缩；长 SQL 和宽表格在自己的区域内滚动，避免撑宽父容器并裁切图表。

## 6. 仍需清楚区分的边界

1. 当前图表分析读取结构化图表数据和确定性描述统计，不是将截图发给视觉模型；不自动证明因果关系。
2. 哈希检查保存内容的一致性，不是不可抵赖签名，不保证模型解释正确，也不保证数据库当前未变化。
3. 查询超时是应用侧等待期限，不保证所有驱动立刻终止数据库端查询；只读数据库权限仍然必要。
4. 常规网页下载的 HTML 仍引用外部静态 JS，网络不可用时可能无法渲染。此次验收导出使用 `--frontend-node-modules` 打包项目现有 Markdown、净化与 ECharts 文件，已验证本地渲染；转移该导出时需要连同 assets 文件夹一起保留。
5. 真实模型有服务可用性、语义和结构化输出风险；应查看运行状态与实际证据，不以“页面没报错”作为结论。
6. 项目没有安装 AntV Chart MCP，也没有向其在线绘图服务发送工业行数据。第三方可视化 MCP 如后续接入，应只承担渲染，数据与证据仍由本项目管理。
