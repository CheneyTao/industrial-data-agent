# 图表选择与模型备用策略

## 图表由谁选择

Web 和 MCP 的完整分析流程使用同一套节点。查询成功后，展示规划器读取原始问题、当前查询任务、全部返回结果的字段画像（类型、空值、基数、数值统计）和前 20 行样例，输出图表类型及语义字段，不生成数据，也不自行编写 ECharts 配置。

目前支持表格、纵向柱状图、横向条形图、折线图、饼/环图、散点图、热力图、堆叠柱状图。程序用完整的已保存查询结果验证字段、数值、类别重复和绘图限制，再生成 ECharts 图表。空值不会变成零。不适合绘图时允许保留表格；图表失败会保留查询结果并标记部分完成。

新合同使用 `dimension`、`measures`、`group_by`，不使用含糊的物理轴名称。横向条形图的 dimension 仍是类别，measures 仍是数值；渲染器决定朝向。长表可以用 group_by 生成多系列折线/比较图，缺失点保持空值，不擅自求和。历史 x/y/category 在入口兼容，新决策保存语义名称。网页保留旧 displayStyle 兼容接口，以已验证 chartOption 为准。

多个不同或未知单位的数值指标在 column/bar/line/scatter 中分面，每个指标使用独立坐标轴，最多四面。不从字段名猜单位，不混用金额、百分比、小时或次数的刻度。stacked_bar 的可加性仍需业务语义支撑。

这属于“模型选型 + 确定性校验和绘制”，不是按问句关键词固定匹配一种图，也不是任意图型生成器。验证不通过时最多反馈重选一次，保留每次 chart_decision（原提案、错误、接受/拒绝、结果来源），不偷偷交换字段。字段校验不能代替业务口径验证。

## 切换边界

- 遇到网络连接错误、超时、HTTP 408/429/500/502/503/504 时，推进到下一个候选；HTTP 404 且还有不同候选时也允许推进。
- 整次网络调用共用有界尝试预算：`max(1 + model_transient_retries, 去重后模型数)`，不是每个模型都重复三遍。历史三个模型最多三次；当前预览主模型加 8 个备用最多九次，仍受任务总时限约束，时限可能早于遍历全部备用而耗尽。保留原有 8 个备用上限，不无限扩展列表。
- HTTP 400/401/普通 403 不换模型。唯一可配置例外是经端点与型号精确匹配、且服务商明确为单模型不可用的错误代码；本机只配置 `AllocationQuota.FreeTierOnly`。403 不因模糊错误文本自动放行。上下文溢出仍有单独预算；SQL 错误仍走 SQL 校验与修正流程。
- 已交付响应的流不切换、不重放，以免拼接两套报告。用户取消会结束请求，不触发备用。
- 主模型正常时不额外调用备用。备用只用于当前请求，不改数据库中的活跃模型，也不自动切换向量模型。
- 全部备用复用同一现有接口与密钥；没有跨平台发送密钥。如果整个接口不可达，换同接口的模型也可能全部失败，不保证绕过服务商故障。

## 本地可追溯性

图执行期间，每一次模型网络尝试保存 `model_call` 证据：节点、用途、调用 ID、尝试序号、请求模型、主/备用标识、服务域名、HTTP 状态或异常类型、耗时、下一候选、最终结果。无须启用 Langfuse 或外部监控，不保存密钥、请求头或原始模型请求文本。

节点异常额外保存 `node_error`，失败步骤也引用该节点已产生的证据。不再仅返回空的“Error in stream processing”。通过既有运行溯源接口和 MCP `get_run_trace` / `get_artifact` 查看。

非流式调用还记录 finishReason、token 用量及实际生成预算/推理开关，不保存私有推理内容。`finish_reason=length`、无可见内容、拒答/过滤、流中断分别报明确错误，不能把空串或截断内容送入 JSON 修复。JSON 修复只处理已完整返回的内容，且与原任务共享总时限；流一旦交付，不因失败重放。

## 可配置的能力与预算

`DATAAGENT_CHAT_REQUEST_PROFILES` 按准确的 endpoint_host + model 配置服务商支持的 enable_thinking / thinking_budget，逐个备用候选解析；未知组合不传这些参数，不从型号名称猜测能力，不影响 Embedding。

本机已验证支持思考开关的自动候选默认 enable_thinking=false，避免结构化规划陷入无界长推理。Qwen 候选的 report-review 通过 purpose_options 单独配置 enable_thinking=true、thinking_budget=2048，给事实核对保留受限推理；不能把所有任务都当作简单 JSON 抽取。深度思考仍有 token 和总时限，不保证语义正确。不是换服务商，也不修改数据库里的活跃模型。官方协议见 [DeepSeek API](https://help.aliyun.com/zh/model-studio/deepseek-api) 与 [深度思考](https://help.aliyun.com/zh/model-studio/deep-thinking)。原始 HTTP 参数在 JSON 顶层，extra_body 只是部分 SDK 的传参方式。

`DATAAGENT_CHAT_TASK_BUDGETS` 配置每种用途的 max_output_tokens 与 timeout_seconds。本机 planner=8192/150s，data-view=2048/60s，report=8192/180s；其他用途保持数据库输出预算，总时限默认 300s。时限包含上下文压缩、网络重试/备用切换与 JSON 修复，不能由嵌套重试无限放大。容量必须适配实际候选模型；预算耗尽会明确失败，不保证任何复杂问题都能完成。

另外 plan-review=2048/90s，report-review=4096/150s。计划执行前检查原问题的时间、指标、粒度和交付物；发现可修正遗漏则进入原有有界重规划，不用全周期汇总替代季度条件。报告从持久化结果生成紧凑但无损的证据包，每份结果仅保留一份列定义和全部返回行；报告与报告核对禁止静默上下文截断。草稿经独立模型调用核对，再视问题有界重写；模型核对不是数学证明，验收仍须独立基准。
